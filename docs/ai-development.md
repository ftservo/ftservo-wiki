# 用 AI 开发飞特舵机项目

这个仓库把教程、约束和官方 SDK 放在同一个上下文中，便于 Codex、Claude Code、Cursor 等能够读取本地项目的 AI 编程工具基于真实 API 开发，而不是凭记忆猜测协议。

## 1. 下载完整仓库

```bash
git clone --recurse-submodules https://github.com/ftservo/ftservo-wiki.git
cd ftservo-wiki
```

在 AI 工具中打开整个 `ftservo-wiki` 文件夹。不要只粘贴一个 SDK 文件；AI 需要同时读取 `AGENTS.md`、相关教程、对应 SDK 示例和具体型号内存表。

## 2. 准备项目事实

向 AI 明确提供：

- 舵机完整型号与系列，以及数据表/内存表文件位置
- TTL 或 RS485、调试板型号、串口名
- 电源电压、ID、波特率
- 开发平台、系统、编译器/框架版本
- 目标功能、运动范围、速度限制和故障安全行为
- 已通过 FD 验证的步骤以及当前错误原文

## 3. 可直接使用的提示词

```text
请先阅读仓库根目录 AGENTS.md、docs/ 中与本任务有关的页面，以及
sdk/<对应SDK> 的 README 和同系列示例。

硬件：<完整型号>，<TTL或RS485>，电源 <电压>，ID <ID>，波特率 <值>，
调试板 <型号>，串口 <端口>。
平台：<操作系统/MCU/开发框架与版本>。
目标：<要实现的功能>。
安全限制：<位置、速度、超时、急停策略>。

先列出你从具体型号资料确认到的寄存器、单位和范围；无法确认的内容不要猜。
然后基于官方 SDK 最接近的示例创建最小可运行项目，加入配置、超时、错误处理、
安全停止和 README。先实现只读 Ping，再实现低速小范围运动。最后给出无需硬件的
测试、真实硬件测试步骤以及仍需人工确认的事项。
```

## 4. 审核 AI 输出

1. 检查是否选对 `SCSCL`、`SMS_STS` 或 `HLSCL`。
2. 将每个地址、长度、单位和范围与目标型号内存表逐项核对。
3. 检查程序启动时不会突然跳到零位或极限位置。
4. 检查异常、Ctrl+C、断线和超时时是否能安全停止并关闭串口。
5. 先做无硬件测试，再单舵机卸载低速测试，最后才安装机械负载。

!!! danger "AI 不能替代型号核对和硬件测试"
    AI 可能生成语法正确但寄存器错误的代码。任何运动指令都必须由熟悉硬件的人员审查，并在可立即断电的环境中逐步验证。

## 后续 Rust SDK

未来 Rust SDK 应作为独立任务推进：先冻结支持矩阵和协议测试向量，再设计串口抽象、类型化内存表、超时/错误模型和跨平台 CI，最后由各系列真实硬件验证。本版本不包含占位实现，避免被误认为可用 SDK。
