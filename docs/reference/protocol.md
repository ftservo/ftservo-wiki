# 协议与内存表

飞特总线舵机采用带设备 ID 的串行数据包通信。SDK 已封装 Ping、读、写和同步写等常用操作；直接实现协议前，应先在对应 SDK 中确认校验、字节顺序、超时与状态包处理。

## 三层信息必须匹配

| 层 | 需要确认 |
| --- | --- |
| 物理层 | TTL 或 RS485、电平、半双工方向、接线与共地 |
| 数据包层 | ID、指令、长度、参数、校验、返回策略 |
| 设备内存表 | 地址、宽度、读写属性、单位、范围、掉电保存方式 |

最常见的错误是数据包能够通信，却使用了另一个系列的寄存器地址或单位。

## 使用内存表

写寄存器前逐项核对：完整型号、内存表版本、地址、数据长度、可写范围、RAM/EEPROM、是否需要先关闭扭矩、是否需要重启。对 ID、波特率、模式、限位和校准参数建立变更记录。

官方入口：

- [通信协议、内存表和调试板资料](https://www.feetechrc.com/service.html)
- [飞特现有在线文档](http://doc.feetech.cn/#/f?q=2506a8cb7928)
- [官方 SDK 源码](https://github.com/ftservo)

!!! danger "禁止盲写"
    不知道完整型号或内存表版本时，不要猜测寄存器地址。错误写入 EEPROM 区可能改变 ID、波特率、工作模式或保护参数，使设备失联或意外运动。
