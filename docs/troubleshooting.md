# 故障排查

先选择当前看到的现象。每次只改变一个条件，并记录变化前后的结果。

| 当前现象 | 从这里开始 | 本轮要确认的结果 |
| --- | --- | --- |
| FD / SDK 找不到总线舵机 | [通信检查](#not-found) | 区分端口、接线与设备响应问题 |
| 能读取，但不运动 | [运动检查](#no-motion) | 确认状态、模式与目标值的适用性 |
| 抖动、掉线、间歇失败 | [稳定性检查](#intermittent) | 找到与负载、供电或通信相关的触发条件 |
| 改完 ID / 波特率后找不到 | [配置变更检查](#changed-id) | 对齐设备与主机的新配置 |
| PWM 无响应、方向或行程异常 | [PWM 检查](#pwm) | 确认该型号的信号要求和控制类型 |
| 空载正常，装配后卡住或异常 | [结构检查](#mechanical) | 定位干涉、预紧或零位问题 |
| 仍无法定位 | [整理支持记录](#support) | 提供可重复的最小复现 |

<span id="not-found"></span>

## FD 或 SDK 找不到舵机

按以下顺序排查，且每次只改变一个条件：

1. 系统是否识别出正确 COM/串口，是否被其它程序占用。
2. 调试板是否匹配 TTL/RS485，USB 线是否支持数据。
3. 舵机是否由符合规格的外部电源供电，是否可靠共地。
4. 当前波特率是否正确；总线上是否有重复 ID。
5. 针序、A/B、信号线和接插件是否正确且接触可靠。
6. 只连接一只舵机，用 FD 与 SDK Ping 交叉验证。

<span id="no-motion"></span>

## 能通信但不运动

- 动力电源可能电流不足或触发限流。
- 扭矩未启用，或设备处于不匹配的运行模式。
- 目标值落在软/硬限位之外，速度或扭矩参数为零。
- 使用了其它系列的寄存器、单位或数据长度。
- 温度、电压、过载等保护已经触发。

先读取状态和当前位置，记录设备返回的错误。停机并支撑好负载后检查机构；确认供电、接线和机械余量，再按[第一次运动](getting-started/first-motion.md)做小范围测试。寄存器必须使用[对应应用层](reference/index.md)，不要通过盲写复位参数来尝试恢复。

<span id="intermittent"></span>

## 舵机抖动或通信间歇失败

检查电源压降、共地、线长、接插件、分支拓扑、波特率和程序收发方向切换。动力线与敏感信号线合理布置，多机同时启动时尤其关注电源瞬态。

<span id="changed-id"></span>

## 修改 ID/波特率后“消失”

记录旧值、新值及写入返回结果；停机并支撑负载后，只连接该设备，让 FD/SDK 使用新 ID 和新波特率读取。是否需要重启、写入是否持久化，以该型号资料为准。若不确定修改结果，保存现场信息，不要连续盲写多个地址。

## PWM 无响应、方向或行程异常 {#pwm}

1. 核对完整型号，确认是位置控制还是连续旋转等控制类型；不要把脉宽直接当作通用角度。
2. 按该型号资料核对针序、供电、共地、信号电平、周期和脉宽范围。
3. 检查控制器实际输出的波形及上电时序，而不只看程序里设置的数值。
4. 对照[型号安装说明](products/index.md)检查零位、舵盘与可用行程，再按 [PWM 入门](getting-started/pwm.md)逐步验证。

PWM 接口不使用总线 ID、波特率或串行寄存器表。资料未确认时，先补齐型号要求再调整信号。

<span id="mechanical"></span>

## 空载正常，装配后卡住或异常

停机并支撑负载，避免松开连接件或关闭扭矩时机构坠落。

- 核对实物后缀与图纸 / CAD 版本，检查安装面、输出轴、舵盘和紧固件是否匹配。
- 检查螺钉长度、轴向预紧、线束弯曲与全行程干涉；不要用持续加大扭矩跨过卡点。
- 核对机械零位、程序零位、正方向和软限位；软件目标范围必须落在机构允许范围内。
- 记录异常发生的位置、方向、负载和照片，区分装配前后变化；已确认释放方法后再进行受控测试。

参照[结构与装配](mechanical/index.md)整理设计交接记录。没有正式尺寸图或适用的 CAD 时，不从产品照片估算关键安装尺寸。
